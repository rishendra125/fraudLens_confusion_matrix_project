Threshold (θ)
The sensitivity dial. If a transaction's fraud score is above this number, the model flags it. Lower = stricter, catches more fraud but also blocks more genuine customers.
True Positive (TP) ✅
The model flagged a transaction as fraud — and it actually was fraud. This is the ideal outcome. Money saved.
False Positive (FP) ⚠️
The model flagged a genuine customer's transaction as fraud by mistake. The customer gets blocked and is frustrated. No money lost, but trust is damaged.
False Negative (FN) 🚨
The model missed a fraud transaction and let it through. The bank loses money. This is the most costly error in financial services.
True Negative (TN) ✅
The model correctly let a genuine transaction through. No error, no cost. This is also a good outcome.
Precision
Out of every transaction the model flagged as fraud, how many were actually fraud? High precision = fewer innocent customers blocked.
Recall
Out of all real fraud cases, how many did the model catch? High recall = fewer frauds slipping through. Also called Sensitivity.
F1 Score
A single number that balances Precision and Recall. 100% is perfect. Useful when both false alarms and missed fraud are costly.
Accuracy
The percentage of all decisions (fraud + genuine) that were correct. Can be misleading — a model that passes every transaction would be 60% accurate but catch zero fraud.
Confusion Matrix
A 2×2 table showing all four outcomes (TP, FP, FN, TN) at once. It tells you not just how many the model got right, but what kind of mistakes it made.
Stakeholder Persona
Two people, same data, different priorities. A Risk Officer wants to catch every fraud even if it means blocking some genuine customers. A CX Head wants to protect customer experience even if a little fraud slips through. Toggle between them to see how the same model looks through different eyes. Risk Officer uses θ=0.35, strict, flags aggressively to minimise missed fraud. CX Head uses θ=0.65, lenient, prioritises customer flow. These are illustrative values; in production, set by the bank's risk team.
Card / Channel Presets
Banks don't use one threshold for everything. A ₹90,000 jewellery card transaction gets scrutinised differently than a ₹50 UPI payment. These presets simulate real-world threshold strategies. High-Value cards use a low threshold (flag aggressively), Micro-txn/UPI uses a high threshold (flag rarely to avoid friction). High-Value Card θ=0.25, Standard Card θ=0.50, UPI/Micro-txn θ=0.70, Debit Low-Risk θ=0.88. Illustrative values; in production, calibrated from historical fraud rates and regulatory guidelines.
Cost Configuration
Cost per missed fraud (FN) = what the bank loses when fraud slips through — investigation fees, chargeback processing, write-off. Cost per false block (FP) = what it costs to wrongly stop a genuine customer — call centre handling, goodwill credits, churn risk. Change these values and watch the cost curve shift.
Fraud Score
A number between 0 and 1 the AI model assigns to every transaction. Closer to 1 = the model thinks it's very likely fraud. Closer to 0 = looks genuine. The threshold decides where to draw the line.
Model Decision
What the model actually does with the transaction — either 🚨 FRAUD (blocks it for review) or ✓ PASS (approves it). Based purely on whether the fraud score is above or below your threshold.
Outcome
The result after comparing the model's decision against the ground truth. ✓ Fraud caught (TP), ✓ Genuine passed (TN), ✗ Fraud missed (FN), ✗ Genuine blocked (FP).
